# tankshift

> 開源的建築熱水系統模擬器：儲熱桶、洗澡尖峰、時間電價加熱排程與碳排。

[English](README.md)

**目前狀態：設計階段**，還沒有可以執行的程式。設計內容見 [`docs/DESIGN.md`](docs/DESIGN.md)（英文）。

## 為什麼做這個

旅館住客一天通常洗一兩次澡，熱水系統卻二十四小時保溫，所以有一部分能源花在待機散熱和循環管路熱損，而不是洗澡本身。這部分有多大，每棟建築不同，tankshift 就是要替個別場所估算出來。另一個極端是晚上入住的畢旅團體：一小時內要用的熱水，可能比儲熱桶裝得還多。

廠商的選型計算器回答的是「設備要買多大」（見設計文件 §5）。tankshift 要回答的是裝好之後的問題：

- 一年花多少錢？能源花到哪裡去了？
- 把加熱移到離峰時段能省多少？會不會有人洗到冷水？
- 40 個學生都在 21:00～22:00 洗澡的那一晚會怎樣？

## 第一版預計功能

- **不綁定場所的引擎**：場所是一組用水曲線和預設參數。第一版附旅館與宿舍。
- **單節點儲熱桶模型**：依 EnergyPlus `WaterHeater:Mixed` 的能量平衡式，每分鐘計算一步。
- **熱源**：電熱、熱泵（COP 隨室外空氣溫度與桶溫變化）、瓦斯鍋爐。
- **時間電價與碳排係數**：臺灣與澳洲，每個數值都附來源與年份。
- **節省報告**：比較基準情境與調整後情境，提供英文與正體中文。
- **退伍軍人菌檢查**：報告會列出儲水溫度低於門檻的時數（第一版是下限值，見設計文件），不會為了省錢犧牲這一項。

第一版不做：分層儲熱桶、電網需量反應訊號、依訂房自動預熱，以及任何實體設備控制。

## 技術選擇
